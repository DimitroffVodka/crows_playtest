Balhaunis

The village map from the MCDM Crows Foundry VTT system. Found an institution and it appears on the plot held for it; raise Prosperity and the homes, fields and woodland fill in behind it. This page runs the system's own map code — no server, no build step, no Foundry.

The village's fortunes, −10 to +10. Homes, fields and dressing are taken in order from the map's slot lists, so a village that falls and recovers gets the same buildings back in the same places.

Institutions

Every institution has a plot whether or not it has been founded. An unfounded one shows the empty plot that is being held for it — the map never rearranges itself to make room.

How it works

Balhaunis is authored, not generated. The roads, the ground, and the position, size and facing of every plot are frozen in canonical-village-layout.mjs — twelve institution slots, sixty-nine homes, twenty-two fields and seventy-seven pieces of dressing, each with a source ID tracing back to the vector export they were lifted from.

What the system decides at play time is only how much of that is standing. buildVillageProjection() takes a village record and returns the Scene's tile list: the authored art for each founded institution and a held plot for each that is not, then an ordered prefix of the homes, fields and dressing sized by Prosperity. Because they are prefixes rather than a random draw, losing Prosperity and regaining it restores the identical village — the same houses, on the same plots.

In Foundry each of those entries becomes a Tile on a 6000×6000 Scene. Here each one is an <image> in an SVG, placed by the same centre, size and rotation. It is the same function producing both.

Looking for the procedural side? An earlier layout engine that generates a village from a seed — boundary, streets, plots, and institutions scored onto the ground they want — is still in the repository and still has a demo of its own.
